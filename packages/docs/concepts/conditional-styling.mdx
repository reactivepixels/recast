# Conditional Styling

Conditional styling allows you to apply styles only when specific combinations of variants and modifiers are met. This enables sophisticated styling logic that goes beyond simple variant or modifier applications, perfect for handling complex design requirements and edge cases.

## Basic conditionals

Define conditionals as an array of rules that specify when certain styles should apply:

```tsx
import { recast } from '@rpxl/recast'

const buttonStyles = recast.styles({
  base: "px-4 py-2 rounded font-medium transition-colors",
  variants: {
    variant: {
      primary: "bg-blue-500 text-white hover:bg-blue-600",
      secondary: "bg-gray-200 text-gray-900 hover:bg-gray-300"
    },
    size: {
      sm: "px-3 py-1.5 text-sm",
      md: "px-4 py-2 text-base",
      lg: "px-6 py-3 text-lg"
    }
  },
  modifiers: {
    disabled: "cursor-not-allowed",
    loading: "cursor-wait"
  },
  conditionals: [
    {
      // Large primary buttons get extra emphasis
      variants: { variant: "primary", size: "lg" },
      className: "shadow-lg font-bold"
    },
    {
      // Disabled primary buttons have different styling
      variants: { variant: "primary" },
      modifiers: ["disabled"],
      className: "bg-blue-300 hover:bg-blue-300"
    },
    {
      // Loading state overrides other styles
      modifiers: ["loading"],
      className: "opacity-75 pointer-events-none"
    }
  ]
})

const Button = buttonStyles(ButtonPrimitive)
```

Usage showcasing conditional styling:

```tsx
// Gets shadow-lg font-bold from conditional
<Button variant="primary" size="lg">
  Large Primary Button
</Button>

// Gets bg-blue-300 hover:bg-blue-300 from conditional
<Button variant="primary" disabled>
  Disabled Primary Button
</Button>

// Gets opacity-75 pointer-events-none from conditional
<Button variant="secondary" loading>
  Loading Secondary Button
</Button>
```

  **Precise control:** Conditionals give you fine-grained control over styling logic, allowing you to handle specific use cases and combinations.
</Check>

## Conditional syntax

Each conditional rule can specify different types of conditions:

<ParamField path="variants" type="object">
  Object specifying which variant values must match. All specified variants must match for the conditional to apply.
</ParamField>

<ParamField path="modifiers" type="array">
  Array of modifier names that must be active. All specified modifiers must be true for the conditional to apply.
</ParamField>

<ParamField path="className" type="string">
  The CSS classes to apply when the condition is met.
</ParamField>

### Variant-only conditionals

Apply styles based on specific variant combinations:

```tsx
const cardStyles = recast.styles({
  base: "rounded-lg border p-6",
  variants: {
    variant: {
      default: "border-gray-200 bg-white",
      primary: "border-blue-200 bg-blue-50",
      destructive: "border-red-200 bg-red-50"
    },
    size: {
      sm: "max-w-sm p-4",
      md: "max-w-md p-6",
      lg: "max-w-lg p-8"
    }
  },
  conditionals: [
    {
      // Large destructive cards get extra emphasis
      variants: { variant: "destructive", size: "lg" },
      className: "ring-2 ring-red-500 shadow-red-200"
    },
    {
      // Small primary cards have subtle styling
      variants: { variant: "primary", size: "sm" },
      className: "border-blue-300"
    }
  ]
})
```

### Modifier-only conditionals

Apply styles based on modifier combinations:

```tsx
const inputStyles = recast.styles({
  base: "px-3 py-2 border rounded transition-colors",
  modifiers: {
    focused: "border-blue-500 ring-2 ring-blue-200",
    error: "border-red-500",
    disabled: "bg-gray-50 cursor-not-allowed"
  },
  conditionals: [
    {
      // Error state when focused gets different ring color
      modifiers: ["focused", "error"],
      className: "ring-red-200 border-red-600"
    },
    {
      // Disabled and error together have muted error styling
      modifiers: ["disabled", "error"],
      className: "border-red-300 bg-red-50"
    }
  ]
})
```

### Mixed conditionals

Combine variants and modifiers in the same conditional:

```tsx
const buttonStyles = recast.styles({
  base: "px-4 py-2 rounded font-medium transition-colors",
  variants: {
    variant: {
      primary: "bg-blue-500 text-white hover:bg-blue-600",
      secondary: "bg-gray-200 text-gray-900 hover:bg-gray-300"
    }
  },
  modifiers: {
    disabled: "cursor-not-allowed",
    loading: "cursor-wait"
  },
  conditionals: [
    {
      // Primary buttons when loading have specific styling
      variants: { variant: "primary" },
      modifiers: ["loading"],
      className: "bg-blue-400 animate-pulse"
    },
    {
      // Secondary buttons when disabled and loading
      variants: { variant: "secondary" },
      modifiers: ["disabled", "loading"],
      className: "bg-gray-100 opacity-60"
    }
  ]
})
```

## Complex conditional patterns

### State-dependent styling

Handle complex component states with conditionals:

```tsx
const alertStyles = recast.styles({
  base: "rounded-md border p-4 flex items-start gap-3",
  variants: {
    variant: {
      info: "border-blue-200 bg-blue-50",
      warning: "border-yellow-200 bg-yellow-50",
      error: "border-red-200 bg-red-50",
      success: "border-green-200 bg-green-50"
    },
    size: {
      sm: "p-2 text-sm",
      md: "p-4 text-base",
      lg: "p-6 text-lg"
    }
  },
  modifiers: {
    dismissible: "relative pr-10",
    animated: "transition-all duration-300",
    prominent: "font-semibold"
  },
  conditionals: [
    {
      // Large error alerts that are prominent get extra styling
      variants: { variant: "error", size: "lg" },
      modifiers: ["prominent"],
      className: "border-red-500 shadow-lg ring-1 ring-red-500"
    },
    {
      // Animated dismissible alerts have specific exit behavior
      modifiers: ["animated", "dismissible"],
      className: "hover:scale-[0.98] data-[state=closed]:animate-out data-[state=closed]:fade-out"
    },
    {
      // Warning alerts that are animated pulse when prominent
      variants: { variant: "warning" },
      modifiers: ["animated", "prominent"],
      className: "animate-pulse"
    }
  ]
})
```

### Responsive conditionals

Create responsive behavior with conditionals:

```tsx
const layoutStyles = recast.styles({
  base: "flex",
  variants: {
    direction: {
      row: "flex-row",
      column: "flex-col"
    },
    spacing: {
      none: "gap-0",
      sm: "gap-2",
      md: "gap-4",
      lg: "gap-8"
    }
  },
  modifiers: {
    responsive: "flex-col md:flex-row",
    centered: "items-center justify-center",
    wrap: "flex-wrap"
  },
  conditionals: [
    {
      // Responsive + column direction creates mobile-first column layout
      variants: { direction: "column" },
      modifiers: ["responsive"],
      className: "flex-col lg:flex-col" // Stay column on all screens
    },
    {
      // Large spacing with wrap gets different gap behavior
      variants: { spacing: "lg" },
      modifiers: ["wrap"],
      className: "gap-6 md:gap-8 lg:gap-12"
    },
    {
      // Centered + responsive gets different alignment at breakpoints
      modifiers: ["centered", "responsive"],
      className: "justify-start md:justify-center lg:justify-between"
    }
  ]
})
```

### Nested component conditionals

Handle complex nested styling with conditionals:

```tsx
const cardStyles = recast.styles({
  base: {
    root: "rounded-lg border bg-white overflow-hidden",
    header: "px-6 py-4 border-b",
    content: "px-6 py-4",
    footer: "px-6 py-4 border-t bg-gray-50"
  },
  variants: {
    variant: {
      default: {
        root: "border-gray-200",
        header: "border-gray-200",
        footer: "bg-gray-50"
      },
      primary: {
        root: "border-blue-200",
        header: "border-blue-200 bg-blue-50",
        footer: "bg-blue-50"
      }
    },
    size: {
      sm: {
        root: "max-w-sm",
        header: "px-4 py-2",
        content: "px-4 py-3",
        footer: "px-4 py-2"
      }
    }
  },
  modifiers: {
    elevated: {
      root: "shadow-lg"
    },
    hoverable: {
      root: "cursor-pointer transition-shadow"
    }
  },
  conditionals: [
    {
      // Primary cards that are elevated get enhanced styling
      variants: { variant: "primary" },
      modifiers: ["elevated"],
      className: {
        root: "shadow-blue-200/50 border-blue-300",
        header: "bg-blue-100"
      }
    },
    {
      // Small hoverable cards have different hover behavior
      variants: { size: "sm" },
      modifiers: ["hoverable"],
      className: {
        root: "hover:shadow-md hover:scale-[1.02]"
      }
    },
    {
      // Primary + hoverable + elevated gets complex hover state
      variants: { variant: "primary" },
      modifiers: ["hoverable", "elevated"],
      className: {
        root: "hover:shadow-xl hover:shadow-blue-200/60 hover:-translate-y-1"
      }
    }
  ]
})
```

## Advanced patterns

### Priority-based conditionals

Order conditionals by specificity, with more specific rules later:

```tsx
const buttonStyles = recast.styles({
  base: "px-4 py-2 rounded transition-colors",
  variants: {
    variant: { primary: "bg-blue-500 text-white", secondary: "bg-gray-200" },
    size: { sm: "px-3 py-1.5 text-sm", lg: "px-6 py-3 text-lg" }
  },
  modifiers: {
    disabled: "cursor-not-allowed",
    loading: "cursor-wait"
  },
  conditionals: [
    // General rules first
    {
      modifiers: ["disabled"],
      className: "opacity-50"
    },
    {
      modifiers: ["loading"],
      className: "opacity-75"
    },
    
    // More specific rules override general ones
    {
      variants: { variant: "primary" },
      modifiers: ["disabled"],
      className: "bg-blue-300 opacity-60" // Overrides general disabled styling
    },
    {
      variants: { variant: "primary", size: "lg" },
      modifiers: ["loading"],
      className: "bg-blue-400 opacity-80" // Most specific, highest priority
    }
  ]
})
```

### Dynamic conditionals with CSS variables

Use conditionals to set CSS custom properties:

```tsx
const dynamicStyles = recast.styles({
  base: "p-4 rounded transition-all duration-[var(--transition-duration)]",
  variants: {
    speed: {
      slow: "",
      normal: "",
      fast: ""
    }
  },
  modifiers: {
    animated: "transform-gpu"
  },
  conditionals: [
    {
      variants: { speed: "slow" },
      className: "[--transition-duration:500ms]"
    },
    {
      variants: { speed: "normal" },
      className: "[--transition-duration:200ms]"
    },
    {
      variants: { speed: "fast" },
      className: "[--transition-duration:100ms]"
    },
    {
      variants: { speed: "fast" },
      modifiers: ["animated"],
      className: "[--transition-duration:50ms] will-change-transform"
    }
  ]
})
```

### Accessibility-aware conditionals

Create accessible component behavior with conditionals:

```tsx
const accessibleButtonStyles = recast.styles({
  base: "px-4 py-2 rounded font-medium transition-colors focus-visible:outline-none",
  variants: {
    variant: {
      primary: "bg-blue-500 text-white hover:bg-blue-600",
      secondary: "bg-gray-200 text-gray-900 hover:bg-gray-300"
    }
  },
  modifiers: {
    disabled: "cursor-not-allowed",
    pressed: "aria-pressed:shadow-inner",
    expanded: "aria-expanded:shadow-md"
  },
  conditionals: [
    {
      // Primary buttons get blue focus ring
      variants: { variant: "primary" },
      className: "focus-visible:ring-2 focus-visible:ring-blue-500"
    },
    {
      // Secondary buttons get gray focus ring
      variants: { variant: "secondary" },
      className: "focus-visible:ring-2 focus-visible:ring-gray-500"
    },
    {
      // Disabled buttons lose focus capabilities
      modifiers: ["disabled"],
      className: "focus:outline-none focus-visible:ring-0"
    },
    {
      // High contrast mode support
      variants: { variant: "primary" },
      className: "contrast-more:border-2 contrast-more:border-blue-800"
    },
    {
      // Reduced motion support
      className: "motion-reduce:transition-none motion-reduce:hover:transform-none"
    }
  ]
})
```

## Best practices

<AccordionGroup>
  <Accordion title="Order conditionals by specificity">
    Place more general conditionals first, then more specific ones to ensure proper override behavior:
    
    ```tsx
    const styles = recast.styles({
      conditionals: [
        // General: applies to all disabled buttons
        { modifiers: ["disabled"], className: "opacity-50" },
        
        // More specific: applies to disabled primary buttons
        { variants: { variant: "primary" }, modifiers: ["disabled"], className: "bg-blue-300" },
        
        // Most specific: applies to large, disabled, primary buttons
        { variants: { variant: "primary", size: "lg" }, modifiers: ["disabled"], className: "bg-blue-200" }
      ]
    })
    ```
  </Accordion>
  
  <Accordion title="Keep conditionals focused and readable">
    Each conditional should have a clear, single purpose:
    
    ```tsx
    // ✅ Good: Clear, focused conditionals
    const styles = recast.styles({
      conditionals: [
        {
          // Loading state styling
          modifiers: ["loading"],
          className: "cursor-wait opacity-75 pointer-events-none"
        },
        {
          // Error state styling
          variants: { state: "error" },
          className: "border-red-500 bg-red-50"
        }
      ]
    })
    
    // ❌ Bad: Complex, multi-purpose conditional
    const styles = recast.styles({
      conditionals: [
        {
          variants: { variant: "primary", size: "lg" },
          modifiers: ["loading", "disabled"],
          className: "bg-blue-300 cursor-wait opacity-50 pointer-events-none shadow-lg"
          // Too many concerns mixed together
        }
      ]
    })
    ```
  </Accordion>
  
  <Accordion title="Use conditionals for edge cases, not core styling">
    Keep your main styling in variants and modifiers, use conditionals for special cases:
    
    ```tsx
    // ✅ Good: Core styling in variants, edge cases in conditionals
    const styles = recast.styles({
      variants: {
        variant: {
          primary: "bg-blue-500 text-white hover:bg-blue-600", // Core styling
          secondary: "bg-gray-200 text-gray-900 hover:bg-gray-300"
        }
      },
      modifiers: {
        disabled: "opacity-50 cursor-not-allowed" // Core modifier
      },
      conditionals: [
        {
          // Edge case: specific styling for disabled primary buttons
          variants: { variant: "primary" },
          modifiers: ["disabled"],
          className: "bg-blue-300 hover:bg-blue-300"
        }
      ]
    })
    ```
  </Accordion>
  
  <Accordion title="Test conditional combinations thoroughly">
    Ensure all conditional combinations work as expected:
    
    ```tsx
    // Test all combinations of your conditionals
    const testCases = [
      { variant: "primary", disabled: true },
      { variant: "primary", loading: true },
      { variant: "primary", disabled: true, loading: true },
      { variant: "secondary", disabled: true },
      // ... test all relevant combinations
    ]
    
    testCases.forEach(props => {
      const classes = buttonStyles.extract(props)
      expect(classes).toMatchSnapshot()
    })
    ```
  </Accordion>
</AccordionGroup>

## Performance considerations

Conditionals are evaluated efficiently, but consider these patterns:

```tsx
// ✅ Good: Stable conditions
const isDisabled = user.role !== 'admin'
const isLoading = mutation.isPending

<Button 
  variant="primary" 
  disabled={isDisabled} 
  loading={isLoading}
>
  Save Changes
</Button>

// ❌ Avoid: Frequently changing conditions that create new combinations
<Button 
  variant="primary"
  disabled={Math.random() > 0.5} // Creates many different combinations
  loading={Date.now() % 2 === 0}
>
  Unstable Button
</Button>
```

<Warning>
  **Cache efficiency:** Stable prop combinations improve cache hit rates. Avoid creating unique combinations on every render.
</Warning>
