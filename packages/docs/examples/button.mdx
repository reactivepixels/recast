# Button Component

This example demonstrates how to build a production-ready button component using all of Recast's features: styles, variants, modifiers, composition, and conditional styling.

<Note>
  This example showcases real-world patterns you can use in your own component library. Each section builds upon the previous ones to create a fully-featured button.
</Note>

## Step 1: Create the primitive component

Start with a clean, unstyled button primitive:

```tsx ButtonPrimitive.tsx
import React, { ButtonHTMLAttributes, forwardRef } from 'react'

interface ButtonPrimitiveProps extends ButtonHTMLAttributes<HTMLButtonElement> {
  children: React.ReactNode
}

export const ButtonPrimitive = forwardRef<HTMLButtonElement, ButtonPrimitiveProps>(
  ({ children, ...props }, ref) => {
    return (
      <button ref={ref} {...props}>
        {children}
      </button>
    )
  }
)

ButtonPrimitive.displayName = 'ButtonPrimitive'
```

<Tip>
  **Clean primitives:** Keep your primitive components focused on functionality, not styling. This separation is key to Recast's power.
</Tip>

## Step 2: Build with composition

Instead of one monolithic style definition, we'll compose multiple focused style objects:

### Foundation styles

Essential button behavior and accessibility:

```tsx foundationStyles.ts
import { recast } from '@rpxl/recast'

export const foundationStyles = recast.styles({
  base: [
    // Core button structure
    "inline-flex items-center justify-center",
    "font-medium transition-colors duration-200",
    
    // Accessibility
    "focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-offset-2",
    "disabled:pointer-events-none disabled:opacity-50",
    
    // Interactive feedback
    "active:scale-95"
  ].join(" "),
  
  modifiers: {
    fullWidth: "w-full",
  }
})
```

### Size variants

Consistent sizing across the design system:

```tsx sizeStyles.ts
export const sizeStyles = recast.styles({
  variants: {
    size: {
      sm: "h-8 px-3 text-sm rounded",
      md: "h-9 px-4 py-2 text-base rounded-md", 
      lg: "h-10 px-6 text-lg rounded-md"
    }
  },
  defaults: {
    variants: { size: "md" }
  }
})
```

### Visual variants

Different visual styles for semantic purposes:

```tsx visualStyles.ts
export const visualStyles = recast.styles({
  variants: {
    variant: {
      primary: [
        "bg-blue-500 text-white",
        "hover:bg-blue-600",
        "focus-visible:ring-blue-500"
      ].join(" "),
      
      secondary: [
        "bg-gray-100 text-gray-900",
        "hover:bg-gray-200",
        "focus-visible:ring-gray-500"
      ].join(" "),
      
      outline: [
        "border-2 border-gray-300 bg-transparent text-gray-700",
        "hover:bg-gray-50 hover:border-gray-400",
        "focus-visible:ring-gray-500"
      ].join(" "),
      
      ghost: [
        "bg-transparent text-gray-700",
        "hover:bg-gray-100",
        "focus-visible:ring-gray-500"
      ].join(" "),
      
      destructive: [
        "bg-red-500 text-white",
        "hover:bg-red-600", 
        "focus-visible:ring-red-500"
      ].join(" ")
    }
  },
  defaults: {
    variants: { variant: "primary" }
  }
})
```

### Enhancement modifiers

Optional visual enhancements:

```tsx enhancementStyles.ts
export const enhancementStyles = recast.styles({
  modifiers: {
    rounded: "rounded-full",
    shadow: "shadow-sm hover:shadow-md",
  }
})
```

### State styles

Loading and interactive states:

```tsx stateStyles.ts
export const stateStyles = recast.styles({
  modifiers: {
    loading: "cursor-wait",
  },
  conditionals: [
    {
      // Loading state overrides hover effects
      modifiers: ["loading"],
      className: "pointer-events-none opacity-75"
    }
  ]
})
```

## Step 3: Advanced conditional styling

Add sophisticated styling logic for complex combinations:

```tsx conditionalStyles.ts
export const conditionalStyles = recast.styles({
  conditionals: [
    // Size-specific adjustments
    {
      variants: { size: "sm" },
      modifiers: ["rounded"],
      className: "rounded-full" // Small buttons are fully rounded
    },
    {
      variants: { size: "lg" },
      modifiers: ["shadow"],
      className: "shadow-md hover:shadow-lg" // Large buttons get bigger shadows
    },
    
    // Variant-specific loading states
    {
      variants: { variant: "primary" },
      modifiers: ["loading"],
      className: "bg-blue-400"
    },
    {
      variants: { variant: "destructive" },
      modifiers: ["loading"], 
      className: "bg-red-400"
    },
    
    // Complex combinations
    {
      variants: { variant: "destructive", size: "lg" },
      className: "font-bold shadow-lg shadow-red-200/50"
    },
    {
      variants: { variant: "outline" },
      modifiers: ["shadow"],
      className: "shadow-sm hover:shadow border-gray-400"
    },
    
    // Accessibility enhancements
    {
      variants: { variant: "ghost" },
      className: "focus-visible:bg-gray-100"
    }
  ]
})
```

## Step 4: Compose the final component

Bring all style objects together:

```tsx Button.tsx
import { recast } from '@rpxl/recast'
import { ButtonPrimitive } from './ButtonPrimitive'
import { 
  foundationStyles,
  sizeStyles, 
  visualStyles,
  enhancementStyles,
  stateStyles,
  conditionalStyles
} from './buttonStyles'

// Compose all style objects in order of specificity
export const Button = recast.compose([
  foundationStyles,    // Most general - foundation behavior
  sizeStyles,         // Size variants
  visualStyles,       // Visual appearance
  enhancementStyles,  // Optional enhancements
  stateStyles,        // Interactive states
  conditionalStyles   // Most specific - complex logic
])(ButtonPrimitive)

// Export types for better TypeScript experience
export type ButtonProps = ComponentProps<typeof Button>
```

```tsx Real-world Usage
function DeleteUserButton({ user, onDelete }: Props) {
  const [isDeleting, setIsDeleting] = useState(false)
  
  const handleDelete = async () => {
    setIsDeleting(true)
    try {
      await onDelete(user.id)
    } finally {
      setIsDeleting(false)
    }
  }
  
  return (
    <Button
      variant="destructive"
      size="sm"
      loading={isDeleting}
      disabled={isDeleting || !user.canDelete}
      onClick={handleDelete}
    >
      {isDeleting ? 'Deleting...' : 'Delete User'}
    </Button>
  )
}
```

## Style extraction for advanced use cases

Use the `.extract()` method for integration with other libraries:

```tsx Style Extraction
// Get computed classes for any combination
const primaryLargeClasses = Button.extract({ 
  variant: "primary", 
  size: "lg",
  shadow: true 
})

// Use with Framer Motion
import { motion } from 'framer-motion'

function AnimatedButton({ children, ...props }) {
  const buttonClasses = Button.extract(props)
  
  return (
    <motion.button
      className={buttonClasses}
      whileHover={{ scale: 1.05 }}
      whileTap={{ scale: 0.95 }}
    >
      {children}
    </motion.button>
  )
}

// Use for server-side rendering
function ServerRenderedButton(props) {
  const classes = Button.extract(props)
  
  return `<button class="${classes}">${props.children}</button>`
}
```

## Testing the button

Test individual style concerns and the composed result:

```tsx Button.test.tsx
import { describe, it, expect } from 'vitest'
import { render } from '@testing-library/react'
import { Button } from './Button'
import { foundationStyles, visualStyles } from './buttonStyles'

describe('Button Component', () => {
  // Test individual style objects
  it('foundation styles include accessibility classes', () => {
    const classes = foundationStyles.extract({})
    expect(classes).toContain('focus-visible:outline-none')
    expect(classes).toContain('disabled:pointer-events-none')
  })
  
  it('visual styles have correct variant classes', () => {
    expect(visualStyles.extract({ variant: 'primary' }))
      .toContain('bg-blue-500')
    expect(visualStyles.extract({ variant: 'destructive' }))
      .toContain('bg-red-500')
  })
  
  // Test composed component
  it('renders with correct default classes', () => {
    const { container } = render(<Button>Test</Button>)
    const button = container.querySelector('button')
    
    expect(button).toHaveClass('inline-flex')
    expect(button).toHaveClass('bg-blue-500') // default primary
    expect(button).toHaveClass('h-9') // default medium size
  })
  
  it('applies conditional styling correctly', () => {
    const { container } = render(
      <Button variant="destructive" size="lg">Delete</Button>
    )
    const button = container.querySelector('button')
    
    expect(button).toHaveClass('font-bold') // from conditional
    expect(button).toHaveClass('shadow-lg') // from conditional
  })
  
  it('handles modifier combinations', () => {
    const classes = Button.extract({ 
      variant: 'primary', 
      loading: true, 
      fullWidth: true 
    })
    
    expect(classes).toContain('w-full')
    expect(classes).toContain('pointer-events-none')
    expect(classes).toContain('opacity-75')
  })
})
```

## Performance considerations

The composed button is highly optimized:

<CardGroup cols={2}>
  <Card title="Memoization" icon="memory">
    All style computations are cached automatically
  </Card>
  <Card title="Composition" icon="puzzle-piece">
    Style objects are composed once, not on every render
  </Card>
</CardGroup>

```tsx Performance Tips
// ✅ Good: Define once, use many times
const Button = recast.compose([...styles])(ButtonPrimitive)

function App() {
  return (
    <>
      <Button variant="primary">Button 1</Button>
      <Button variant="secondary">Button 2</Button>
    </>
  )
}

// ❌ Bad: Composing on every render
function App() {
  const Button = recast.compose([...styles])(ButtonPrimitive) // Inefficient
  return <Button>Test</Button>
}

// ✅ Good: Stable prop values
const [isLoading, setIsLoading] = useState(false)
<Button loading={isLoading}>Save</Button>

// ❌ Bad: New values every render
<Button loading={Date.now() % 2 === 0}>Save</Button>
```

## Key patterns demonstrated

This button example showcases several important Recast patterns:

<AccordionGroup>
  <Accordion title="Composition over inheritance">
    Instead of one massive style object, we composed focused style modules that can be reused across components.
  </Accordion>
  
  <Accordion title="Semantic variants">
    Variants like `primary`, `secondary`, `destructive` communicate intent rather than just visual properties.
  </Accordion>
  
  <Accordion title="Layered conditionals">
    Conditionals handle edge cases and complex combinations while keeping the base variants simple.
  </Accordion>
  
  <Accordion title="Accessibility by default">
    Foundation styles include focus management, keyboard interaction, and screen reader considerations.
  </Accordion>
  
  <Accordion title="Performance optimization">
    Composition happens once, style computation is cached, and the API encourages stable prop usage.
  </Accordion>
</AccordionGroup>
